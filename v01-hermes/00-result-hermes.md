2. 项目概述

2.1 项目背景

现状痛点

人事管理是公司人才发展的核心环节。当前存在以下痛点：

（1）技术岗位聘任流程效率低下

纸质申请反复修改、传递慢，授权周期长

人工核验资质，易出错

技术岗位聘任信息分散，无法统一管理

（2）试用期考核缺乏系统化管理

试用期考核任务书依赖纸质协议，易丢失

考核指标不规范，占比校验依赖人工

考核结果无法与培训系统联动

（3）人事档案和信息使用管理不规范

人事档案转入归档依赖纸质流程

人力资源信息使用申请缺乏电子化审批

数据敏感等级无明确定义，存在安全隐患

（4）干部导师管理缺失

导师与徒弟结对无系统记录

赠书记录分散，无法追溯

每名导师最多带三名徒弟，缺乏管控

建设必要性

因此，开发建设一套功能完善的人事管理系统，实现技术岗位聘任、试用期考核、人事管理、干部导师库等业务的线上化管理，不仅是解决当前痛点、提升管理效能的迫切需要，更是公司数字化转型的重要组成部分。

2.2 项目目标

流程线上化：所有人事审批流程实现在线申请、多级审批、自动归档

数据集中化：建立统一的人事数据台账，支持查询、筛选、导入、导出

权限精细化：按角色定义数据查看范围和操作权限，保障数据安全

提醒自动化：系统自动提醒关键时间节点（职称初定、假期提醒等）

4.3.1 试用期考核任务书签订

需求名称

试用期考核任务签订

业务场景

培训系统师傅与徒弟职责协议审核通过后，人资系统产生一条师傅可编辑的待办数据，明确试用期考核指标和占比，师傅发起、徒弟确认、科长审核后生效

价值点

师徒协议线上化；考核指标标准化；占比自动校验100%；全程留痕

功能描述

全局按钮： 无数据来源： 数据从培训系统同步过来（试用期考核任务书签订审核通过）列表字段： 姓名，所在部/科，合同期限，员工号，入职时间，试用期结束时间，入职途径，拟聘岗位名称表单字段： 姓名、所在部/科、合同期限、员工号、入职时间、试用期结束时间、学历、入职途径、拟聘岗位名称（均同步）子表：基础素质列名：考核项，考核项说明，占比，详情评分，评分办法，备注考核项：责任心（能从整体出发对自身岗位职责与目标负责，占比8%，关键事件法，文本录入）；主动性（主动承担工作任务，占比8%，关键事件法，默认文本）；团队意识（积极关注团队目标，占比8%，关键事件法，默认文本）；学习领悟（善于总结学习，占比8%，关键事件法，默认文本）；沟通协调（善于与人沟通交流，占比8%，关键事件法，默认文本）子表：专业素质： 评标子表新增即可，师傅自行增加指标，设置占比校验规则： 所有占比加起来等于100%

角色及权限

师傅：编辑/发起；徒弟：确认；科长：审核；人资：查看所有状态数据

数据描述

徒弟信息、考核指标、占比、审批记录

输入/前置条件

培训系统师傅与徒弟职责协议审核通过

输出/后置条件

生成任务书记录，人资可掌握进度

基本流程

培训系统协议通过 → 人资系统产生待办 → 师傅编辑（专业素质指标+占比,录入详细评价） → 提交徒弟 → 徒弟确认 → 科长审核 → 生效

纸质申请电子化；按敏感等级分级审批；权限自动管控；操作日志追溯

功能描述

列表字段： 申请人姓名，申请人工号，所在部门，申请日期，申请数据敏感等级，审批状态，查看权限有效期，操作表单字段： 申请人姓名，申请人工号，所在部门，申请日期，是否涉密信息（是/否）、信息使用需求描述，信息使用用途/方式数据敏感等级定义：- 高敏感：身份证号码、银行卡号、家庭住址、联系电话（私人）、薪资明细等- 低敏感：员工工号、部门名称、岗位类别等公开性较高的基础信息。员工姓名、岗位、入职日期、部门归属、考勤记录等审批流程：- 低敏感数据：申请人发起 → 业务部门科长审批 → 人资科长审批 → 审批通过（可查看数据）- 高敏感数据：申请人发起 → 业务部门科长审批 → 业务部门经理审批 → 人资科长审批 → 人资部门经理审批 → 审批通过（可查看数据）

角色及权限

员工：发起；业务部门科长：审核（低敏感/高敏感）；业务部门经理：审核（仅高敏感）；人资科长：审核；人资部门经理：审核（仅高敏感）

数据描述

申请信息、敏感等级、审批记录、权限有效期、操作日志

特殊逻辑

权限管理规则：（需要评估是否可以实现）- 审批通过后，系统自动授予申请人对应申请数据的查看权限，权限范围严格匹配申请内容。- 查看权限有有效期限制（若申请时填写使用期限，按期限生效；未填写则默认有效期为7个工作日）- 系统记录申请人查看数据的操作日志（查看时间、查看内容、查看时长）

输入/前置条件

员工需要使用人力资源信息

输出/后置条件

审批通过后授予查看权限，权限到期自动失效

基本流程

员工发起 → 按敏感等级分级审批 → 审批通过授予权限 → 有效期届满自动失效
